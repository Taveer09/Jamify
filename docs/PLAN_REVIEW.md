# Jamify — независимая критика плана

2026-11-01, Asia/Oral. Ревьюер: отдельный subagent Plan, GPT-6 Astra, effort xhigh, независимый контекст. Вход: SPEC.md, PLAN.md, TASKS.md. Запрос: «Что здесь сломается, что лишнее, что забыли?» Реальные Spotify-пробы не проводились, продуктовый код не создавался.

Результат: архитектура выполнима; распределение Sol/Astra/Luna разумно. До представления пользователю исправлены три замечания P1 и два P2. Это ревью плана, а не доказательство работоспособности API.

| Приоритет | Находка | Изменение в итоговом плане |
|---|---|---|
| P1 | В OAuth grant нет user-read-email для SDK | Добавлены scope, официальный источник и фактическая SDK-проба на S0; email не сохраняется |
| P1 | sourceUri предполагает доступность удалённого linked_from | observedUri и identityConfidence в контракте, отдельный relinking-гейт, блокировка опасных действий для неоднозначных записей |
| P1 | После собственного apply baseline устаревает и продолжение прохода не определено | runId/reviewedUris, атомарная локальная финализация нового baseline и undo, восстановление журнала перед следующей записью; сценарий 25/apply/reload/26/second apply |
| P2 | entryKey включает snapshot/index и не годится для сверки после удаления | CanonicalItem без UI keys и mutable metadata, проверка порядка/повторов; явный предел проверки непрозрачных null-записей |
| P2 | Recovery копии оставлен на усмотрение исполнителя | targetPlaylistId/expectedCanonical/confirmedPrefix/pendingBatch в журнале; проверка всего target после reload; unknown create не повторяется автоматически |

Дополнительные изменения: убрана необязательная Terra, чтобы оставить три понятные роли; оценки названы предварительными и пересчитываются после S0; уточнены доступ к токенам при смене аккаунта, сбой журнала и Spotify-атрибуция/размещение обложек.

Сумма оценок проверена: 30 часов, с запасом 30% — 39 часов. До S4 включительно 17 / 22.1 часа. Ожидание Developer App и масштаб исправлений на S9 могут увеличить сроки.

Осталось проверить при реализации: Developer App и allowlist; реальная семантика DELETE повторных URI; source/playback mapping и relinking; работа SDK/Connect в целевых браузерах; API копирования и полное восстановление после прерывания. Без этих проб не заявлять полную поддержку live-сценариев.

Согласование пользователя: ожидается. S0–S9: не начаты.
