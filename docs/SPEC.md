# Jamify — рабочая спецификация

Статус: реализация согласована пользователем 2026-11-01, Asia/Oral. Начат S0. Название: Jamify.
Основание: пользователь хочет разобрать свой Spotify-плейлист свайпами с прослушиванием и выложить проект на GitHub. Spotify Premium у пользователя есть.

## Результат v1

Адаптивное веб-приложение: вход через Spotify → выбор своего плейлиста → случайная очередь без повторных карточек → музыка и решение → проверка изменений → применение → проверенный результат. Свайп вправо оставляет композицию, влево помечает на удаление. Исходный порядок оставшихся треков сохраняется.

## MUST

- Реальные OAuth PKCE, чтение своего обычного плейлиста, воспроизведение через Web Playback SDK; управление открытым Spotify — запасной вариант.
- Карточки, кнопки и клавиатура; keep/remove/skip, отмена решений до применения, непрерывная очередь всех доступных уникальных треков без окон по 25, продолжение после перезагрузки.
- «Применить и продолжить» после сессии сохраняет новый baseline и просмотренные треки; уже применённые решения не возвращаются в undo и не отправляются повторно.
- Решение remove относится ко всем вхождениям одного исходного URI; число вхождений явно показано. Поведение удаления сначала подтверждается живой пробой.
- Отдельное действие для точных дублей: оставить первую копию каждого URI в новой приватной очищенной копии плейлиста. Исходник сохраняется. Порядок определяется исходным списком, а не порядком свайпов.
- Экран предварительного просмотра, журнал применения, обнаружение изменений исходника, обработка частичного результата, проверка удалений и содержимого копии.
- Локальные файлы, недоступные записи и эпизоды не теряются молча. В режиме удаления они сохраняются; создание очищенной копии блокируется, если хотя бы один сохраняемый элемент нельзя воспроизвести в ней через API.
- Неоднозначная идентичность трека при relinking исключает его удаление и автоматическое объединение дублей. Проверка непрозрачных null-записей ограничивается тем, что действительно сообщает API.
- Демо без аккаунта на вымышленных данных с локальным тестовым аудио; понятная инструкция самостоятельного запуска со своим Client ID.
- Тесты опасной логики и пользовательских сценариев, production build, CI, README и скриншоты.

## SHOULD / COULD после v1

SHOULD: сравнение похожих изданий вручную, русский/английский интерфейс, фильтры очереди, улучшенная работа на мобильных браузерах.
COULD: установка как PWA, перенос между плейлистами, десктопная оболочка.

## Границы

Обычный вход: одна кнопка «Войти через Spotify», Client ID настроен владельцем Jamify один раз. Отдельное приложение Spotify не требуется каждому пользователю. Собственный Client ID остаётся опцией для разработчика, который самостоятельно запускает копию проекта; он спрятан в настройках разработчика. Первоначальный live-доступ — закрытая бета до лимита Development Mode, а не массовый публичный сервис.

v1 предназначена для личного использования, самостоятельного запуска и GitHub-портфолио. Публичное демо доступно без входа; свободный массовый вход в одну Spotify-интеграцию не обещается. Изменение исходника в v1 ограничено своими обычными плейлистами без совместного редактирования. По дополнительному поручению пользователя добавлен отдельный read-only разбор медиатеки: свои и доступные совместные плейлисты, а также Liked Songs. Сохранённые чужие плейлисты видны, но чтение их треков может быть запрещено Spotify. AI, музыкальные рекомендации, серверная БД, оплата и анализ аудио не нужны.

Работы с аккаунтом и изменение реальных плейлистов в рамках текущего планирования не выполняются. Код начинается после согласования плана. Публикация репозитория/деплой — отдельное действие после готовности локального результата.

## Критерий приёмки

На собственном тестовом плейлисте: авторизоваться, прослушать нужный трек, принять 10 решений, отменить одно, продолжить после перезагрузки, применить выбранные удаления; повторное чтение показывает ожидаемый порядок и количество вхождений. Отдельно создать очищенную копию с одним вхождением каждого оставленного URI. Демо проходит без токенов и запросов к Spotify. При смене трека карточка не выдаёт старый звук за новый.

## Уточнения пользователя от 2026-11-01

Разбирать весь плейлист без остановки на25. Повторные вхождения одного URI объединяются в карточку; число вхождений видно. Предел загрузки10 000 записей сохраняется с явной ошибкой, без тихой обрезки; локальные/недоступные записи не попадают в музыкальную очередь и отражаются в счётчике исключений. Тёмная палитра Spotify закреплена последним прямым запросом: #121212/#181818/#282828, #1ed760. Две основные кнопки, дополнительные действия в меню, физический свайп мышью и стрелки. Главная / открывает настоящую медиатеку, /demo остаётся вымышленным режимом, /diagnostics — S0. В live свайпы пока только сохраняют/экспортируют решения, без удаления/копии; открытый DELETE gate не обходится.
