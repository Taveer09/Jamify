# Jamify

Переслушай свой плейлист и оставь любимое. Проект приложения для разбора Spotify-плейлистов свайпами.

Сейчас реализуется **S0**: подключение Spotify, чтение плейлистов, браузерный плеер и изолированная проверка API на отдельном тестовом плейлисте. В `/demo` уже можно прослушивать вымышленные треки, оставлять/убирать/пропускать, отменять решения и применять их после предпросмотра. Жесты и основной live-сценарий уборки ещё не реализованы. Локальные тесты не подтверждают работу реального аккаунта.

Обычному пользователю достаточно **«Войти через Spotify»**. Client ID один раз задаёт владелец Jamify; создавать Spotify-приложение каждому пользователю не нужно. Настройки разработчика предназначены для самостоятельного запуска копии проекта.

Live-версия пока рассчитана на закрытую бету: Development Mode разрешает до пяти добавленных Spotify-аккаунтов. Расширенный доступ требует отдельного одобрения Spotify; в опубликованных критериях — организация и минимум 250k MAU. Деплой на Vercel не снимает этот лимит. [Условия доступа](https://developer.spotify.com/documentation/web-api/concepts/quota-modes).

Демо после локального запуска: [http://127.0.0.1:5173/demo](http://127.0.0.1:5173/demo). Аккаунт и Client ID для него не нужны. Аудио и обложки созданы для проекта, Spotify в демо не вызывается.

## Запуск

Нужен Node.js 22.12 или новее. Склонируй репозиторий и запусти:

```sh
git clone https://github.com/Taveer09/Jamify.git
cd Jamify
npm ci
cp .env.example .env.local
npm run dev
```

Открой `http://127.0.0.1:5173`. Владелец самостоятельного экземпляра задаёт публичный Client ID в `VITE_SPOTIFY_CLIENT_ID` внутри `.env.local` либо в раскрываемых «Настройках разработчика». Остальные пользователи видят обычную кнопку входа. Client Secret и пароль приложению не нужны. Если `.env.local` уже существует, сохрани его настройки, а не перезаписывай командой `cp`.

В [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) создай приложение, выбери Web API/Web Playback SDK и зарегистрируй Redirect URI `http://127.0.0.1:5173/callback`. Для работы интеграции нужен Spotify Premium; новые Development Mode приложения ограничены allowlist. [Правила Spotify](https://developer.spotify.com/documentation/web-api/concepts/quota-modes).

## Проверки

```sh
npm run check
npm run test:capabilities
npx playwright install chromium webkit
npm run test:e2e
```

Автотесты работают на фикстурах и не меняют Spotify. Реальную пробу пользователь запускает сам в интерфейсе после входа. В режиме S0 запросы удаления направляются только в одноразовый плейлист, созданный этой пробой. После неоднозначного ответа запись не повторяется автоматически. Оригинальные плейлисты доступны для чтения.

Технологии: React, TypeScript, Vite, Zod, Vitest, Playwright. Минимальные auth/HTTP/SDK-адаптеры развиваются дальше по плану; серверная БД и AI API не используются.

Refresh token и одноразовый PKCE сохраняются только в хранилище вкладки; access token живёт в памяти. Отключение аккаунта очищает авторизацию вкладки, но не удаляет созданный тестовый плейлист и его диагностический журнал. Закрытие вкладки завершает локальную авторизацию. Не публикуй `.env.local`, данные аккаунта или токены.
